# しるし / Shirushi v0.1 Preview 技術概要

この文書は、Shirushi v0.1 Previewが利用する技術、その組み合わせ方、確認結果の意味、現在の限界を説明します。

一般的な使い方は[README](../README.md)を参照してください。この文書ではREADMEより一段詳しく技術構成を説明しますが、内部の検証手順や研究上の詳細な失敗条件は扱いません。

## 1. Shirushiの目的と技術的な範囲

Shirushiは、画像へAI利用に関する意思を機械可読な形式で記録し、後から確認できるWindows向けツールです。

現行のv0.1 Previewでは、次の意思表示を固定設定として扱います。

> AIによる学習・生成利用を希望しない

Shirushiが行うのは、この意思表示を画像に記録し、対応する情報を後から確認できるようにすることです。AIサービスそのものを制御する機能ではありません。

すべてのAIサービスが記録情報を読み取るとは限りません。また、読み取ったサービスが意思表示を尊重することも保証しません。AI学習やAI生成を直接停止する機能ではありません。

## 2. 使用している技術

Shirushiは、C2PA、CAWG Rights、TrustMarkを組み合わせて利用意思を記録します。それぞれは異なる役割を持ちます。

### C2PA

C2PAは、画像に付随する来歴や記録情報を構造化して扱うための仕組みです。記録内容をまとめたmanifestと、そのmanifestに対する署名を扱います。

Shirushiでは、AI利用に関する意思表示や関連情報を画像と結び付けるためにC2PAを利用します。また、保存した画像を確認するときは、C2PAに記録された内容と画像との技術的な整合性を検証します。

C2PAを使用していても、あらゆる加工や改変を常に検出できるとは限りません。画像の扱われ方によっては、C2PA情報そのものが失われることもあります。

### CAWG Rights

CAWG Rightsは、AI利用に関する意思を構造化して記述するための仕組みです。

Shirushi v0.1 Previewでは、AIによる学習・生成利用を希望しないという固定の意思表示を、CAWG Rightsを利用して記録します。

CAWG Rightsは、著作権などの法的権利そのものを発生させたり証明したりするものではありません。また、AIサービスへ利用条件を強制する仕組みでもありません。

### TrustMark

TrustMarkは、画像の画素側へ識別情報を埋め込む補助的な仕組みです。メタデータとは異なる経路で、画像に識別の手掛かりを残すことを目的としています。

Shirushiでは、TrustMarkによる識別情報と、C2PA内に記録された対応するsoft binding情報との一致を確認できるようにしています。

この対応付けにより、確認時にC2PA側の情報とTrustMark側の識別情報が整合しているかを調べられます。ただし、TrustMarkの識別情報だけが残っていても、AI利用条件全体を確認または復元できたとは扱いません。

## 3. しるしを付ける処理

Shirushiで画像にしるしを付ける処理は、次の流れで行われます。

1. ユーザーが画像を選択します。
2. 固定されたAI利用に関する意思を記録します。
3. TrustMarkによる識別情報を画像の画素側へ付与します。
4. 利用意思と関連情報を含むC2PA情報を作成し、署名します。
5. 元画像を上書きせず、別の画像ファイルとして保存します。
6. 保存後の画像を読み取り、記録内容の技術的な整合性を確認します。

出力ファイルは、元のファイル名に`_rights`を付けて、元画像と同じフォルダーへ保存されます。例えば、`photo.jpg`を選択した場合は、`photo_rights.jpg`が保存予定名になります。

同じ名前の出力ファイルがすでに存在する場合は上書きしません。元画像も直接変更しません。

## 4. しるしを確認する処理

Shirushiは、画像から確認できた情報を次の4つの状態に分けて表示します。

### 完全性を確認済み

記録されたAI利用に関する意思表示（CAWG Rights）、C2PA、TrustMarkなどについて、Shirushiが確認対象としている技術的な整合性を確認できた状態です。

これは、作者本人、著作権者本人、著作権の保有、法的有効性、Production Trustを確認したという意味ではありません。

### 意思表示なし

Shirushiが対象のAI利用に関する意思表示を確認できなかった状態です。

この状態は、AI利用の許可も拒否も意味しません。画像に対象の情報が記録されていない場合だけでなく、Shirushiが確認できる形で残っていない場合もあります。

### 識別情報のみ

TrustMarkなどの識別情報が残っている可能性はあるものの、対応するAI利用条件全体を確認できない状態です。

識別情報を検出できたことと、AI利用に関する意思表示や利用条件を復元できたことは別です。

### 確認できません

情報が存在する可能性はあるものの、その内容や完全性を確認できない状態です。

これは、意思表示が見つからない状態とは区別されます。確認できない情報を、正常な意思表示として扱うことも、意思表示が存在しないと断定することもありません。

また、暗号署名を数学的に検証できることと、その署名者を社会的・制度的に信頼できることは別の問題です。Shirushiは、この違いを分けて扱います。

## 5. v0.1 Previewの署名と信頼性

Shirushi v0.1 Previewでは、C2PA情報へ署名するために、`c2patool`が提供する開発・テスト用途の資格情報を使用しています。

この署名は、記録内容の技術的な検証に使用できます。ただし、Production Trustを備えた正式な信頼済み署名ではありません。

現行のv0.1 Previewは、次の事項を証明または保証しません。

- 署名した人物が実際の作者本人であること
- 利用者が著作権者本人であること
- 利用者が著作権を保有していること
- 記録した情報が法的効力を持つこと
- AIサービスが記録内容を認識または遵守すること

暗号署名が数学的に正しいことを確認できても、その署名者をどこまで信頼できるかは、証明書や信頼の仕組みによって別途判断されます。v0.1 Previewは、その信頼性を確認するProduction Trustには対応していません。

## 6. ローカル処理と外部通信

画像へのしるしの付与と確認は、基本的にユーザーのPC内で処理します。Shirushi自身には、処理対象の画像ファイルを外部サービスへアップロードする処理はありません。

一方で、すべての利用場面で通信が発生しないわけではありません。

TrustMarkのモデルファイルは、Release packageに同梱していません。必要なモデルがユーザーの環境にない場合は、公式の配布元から取得してユーザー用キャッシュへ保存します。この取得時には通信が発生します。

また、確認対象の画像に外部C2PA参照情報が含まれている場合は、その確認に伴って通信が発生する可能性があります。

Shirushiには、製品テレメトリ、利用状況の分析、リモートログ送信は実装していません。通信、モデル取得、ログ、一時ファイル、キャッシュの詳しい取り扱いは[プライバシー情報](../PRIVACY.md)を参照してください。

## 7. 対応形式と情報の残存性

Shirushi v0.1 Previewは、次の画像形式の付与と確認に対応します。

- PNG
- JPEG / JPG

Shirushiが記録したC2PA情報、CAWG Rights、TrustMarkの識別情報、その他のメタデータが、加工後も残り続けることは保証しません。

例えば、次の操作によって記録情報の一部または全部が失われる可能性があります。

- 画像編集ソフトによる再保存
- 画像形式の変換
- メタデータの削除
- 画像の切り抜き
- サイズ変更
- 回転
- 他の画像編集ソフトによる加工
- SNSや画像共有サービスへのアップロード

Shirushi自身も、入力画像に含まれるすべてのメタデータを完全に保存するものではありません。重要な元画像やメタデータがある場合は、元画像を保持してください。

## 8. 配布構成と第三者コンポーネント

Shirushi v0.1 PreviewのWindows向けRelease packageには、高レベルでは次の要素が含まれます。

- `Shirushi.exe`
- 配布物に含まれるPython実行環境
- C2PA情報を扱うための`c2patool`
- 実行に必要な設定
- README、製品上の注意事項、プライバシー情報などの文書
- 第三者コンポーネントのライセンス情報

TrustMarkのモデルファイルはRelease packageに同梱しません。必要になった時点で公式の配布元から取得します。

Release packageには、Shirushi独自の本番用の秘密鍵やProduction Trust用の資格情報は含みません。現行のv0.1 Previewでは、`c2patool`が提供する開発・テスト用途の資格情報を利用して署名します。これはProduction Trustを備えた署名ではありません。

第三者コンポーネントとライセンスの詳しい情報は、[第三者コンポーネントに関する表示](../THIRD_PARTY_NOTICES.md)を参照してください。
